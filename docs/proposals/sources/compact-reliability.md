# Source note — reliability of Claude Code `/compact` and auto-compact

**What this file is:** research done on 2026-10-01 into how well `/compact` and auto-compact keep working context across a milestone of 3–10 related tasks, for the owner's trial of (a) a fresh session per task that rereads the records, (b) one session running `/compact <instructions>` at each task boundary, and (c) one long session, on Claude Code 2.1.286. Sources: the official docs on that date, Anthropic's API docs and engineering posts, and the anthropics/claude-code CHANGELOG and issue tracker. Claims no primary source confirms are marked **unconfirmed**. Authority: none.

**Status:** MAINT-0006 (v1.10.1) adopted a new session at each signing round, never one carried over by `/compact`; a fresh helper agent per task inside a round; and the CLAUDE.md section in `templates/claude/compact-instructions.md`. Still proposed: the task-boundary `/compact` text below, a `SessionStart` hook with matcher `compact`, and the measured trial.

## What the docs establish

- **What `/compact` does.** `/compact [instructions]` summarises the conversation, with optional focus instructions ([commands](https://code.claude.com/docs/en/commands)). The automatic pass first clears older tool outputs, then summarises; "detailed instructions from early in the conversation may be lost" ([how Claude Code works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)).
- **When auto-compact fires.** With no window set: about 967K tokens on native 1M-window models (Sonnet 5, Fable, Opus 4.7 and later), 200K on 200K-window sessions, otherwise the model's limit ([model config](https://code.claude.com/docs/en/model-config#default-auto-compact-thresholds)). If one large output refills the window after each summary, it stops with `Autocompact is thrashing` ([troubleshooting](https://code.claude.com/docs/en/troubleshooting#auto-compaction-stops-with-a-thrashing-error)).
- **What survives** ([context window](https://code.claude.com/docs/en/context-window#what-survives-compaction)):
  - Re-injected from disk: project-root CLAUDE.md, unscoped rules, auto memory, the plan-mode plan; git status is taken fresh.
  - Up to five recently modified files are re-read; one over 5,000 tokens returns as a path only. Invoked skills return, capped at 5,000 tokens each and 25,000 in total.
  - Summarised away: anything said only in conversation, path-scoped rules, nested CLAUDE.md files, context hooks added.
- **The task list may not exist.** Tasks persist across compaction (**unconfirmed**: the review could not find this wording on [interactive mode](https://code.claude.com/docs/en/interactive-mode#task-list)), but the task tools are on by default only up to Opus 4.7, Sonnet 4.6 and Haiku 4.5 ([tools reference](https://code.claude.com/docs/en/tools-reference#task-tool-availability)). On current models task state lives only in the conversation unless `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`.
- **Anthropic's own caveats.** "Overly aggressive compaction can result in the loss of subtle but critical context"; note-taking "excels for iterative development with clear milestones" ([context engineering, 2025-09-29](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). In Anthropic's long-running harness, compaction "doesn't always pass perfectly clear instructions to the next agent"; the fix was fresh sessions reading a progress file and the git log ([harnesses, 2025-11-26](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
- **Compact, clear or start fresh.** `/clear` between unrelated tasks and after two failed corrections; a fresh session to execute a finished spec ([best practices](https://code.claude.com/docs/en/best-practices#manage-your-session)); `/compact` "for natural breaks between tasks" ([prompt caching](https://code.claude.com/docs/en/prompt-caching#how-the-cache-is-organized)).

## How to steer compaction

1. **Focus text on manual `/compact`.** It applies to the manual pass; for automatic compaction the hooks reference gives a `PreCompact` hook's `custom_instructions` as typically null or empty ([hooks](https://code.claude.com/docs/en/hooks#precompact-input)).
2. **A "Compact Instructions" section in project-root CLAUDE.md** steers every compaction, automatic ones included ([how Claude Code works](https://code.claude.com/docs/en/how-claude-code-works#when-context-fills-up)); the heading is free-form because the compactor "matches on intent" ([Agent SDK](https://code.claude.com/docs/en/agent-sdk/agent-loop#automatic-compaction)). Mid-session edits apply only after `/clear`, `/compact` or restart ([prompt caching](https://code.claude.com/docs/en/prompt-caching#editing-claude-md-mid-session)); [#92949](https://github.com/anthropics/claude-code/issues/92949) reports auto-compaction re-injecting the copy from the last prompt, not disk.
3. **Hooks** ([hooks](https://code.claude.com/docs/en/hooks#postcompact), [guide](https://code.claude.com/docs/en/hooks-guide#re-inject-context-after-compaction)): `SessionStart` with matcher `compact` adds its output after each compaction; `PreCompact` can block (a blocked proactive pass is skipped, a blocked recovery pass fails the request); `PostCompact` receives the summary as `compact_summary`. No hook can edit the summary.
4. **Timing** ([model config](https://code.claude.com/docs/en/model-config#set-the-auto-compact-window), [env vars](https://code.claude.com/docs/en/env-vars)): `/autocompact <100K–1M>` or `CLAUDE_CODE_AUTO_COMPACT_WINDOW` sets the window; `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` can only lower it; `autoCompactEnabled: false` or `DISABLE_AUTO_COMPACT=1` stops the automatic pass but keeps `/compact`; `DISABLE_COMPACT=1` stops both.
5. **Partial summaries.** `/rewind` → "Summarize from here" or "Summarize up to here", with optional guidance ([checkpointing](https://code.claude.com/docs/en/checkpointing#guide-a-summary)).

## Cost model

- **Mechanism** ([prompt caching](https://code.claude.com/docs/en/prompt-caching#compacting-the-conversation)). Every request re-sends the full context; the cache matches the exact prefix. Compaction invalidates the conversation layer by design. While the cache is warm, the summary request reads the prefix from cache and "costs a fraction of what the context size suggests"; once it has expired, it reprocesses the whole history uncached. `/clear` "costs nothing" ([costs](https://code.claude.com/docs/en/costs)).
- **Prices** ([API pricing](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#pricing)): 5-minute cache writes 1.25× base input, 1-hour writes 2×, reads 0.1× (0.05× on Opus 5.5, 0.025× on Fable 5.1). Opus 5.5 per million tokens: $4 input, $5/$8 writes, $0.20 reads, $20 output.
- **Lifetime** ([TTL](https://code.claude.com/docs/en/prompt-caching#which-ttl-each-request-gets)): reset on each hit. Main conversation: one hour on a subscription within plan usage, otherwise five minutes unless `promptCacheTtl` is `1h`; compaction and subagents mostly five minutes. Consecutive sessions share a cached prefix only if the startup git snapshot matches ([scope](https://code.claude.com/docs/en/prompt-caching#cache-scope)).
- **Illustrative arithmetic (the note-taker's, Opus 5.5).** Every request pays the read rate on everything carried: 150K tokens through a 100-request task is about $3. Rereading 40K tokens of records in a fresh session costs about $0.32 to cache, then the same read rate. A warm `/compact` costs about one read plus the summary's output. A pause longer than the cache lifetime makes the next turn, or `/compact`, reprocess everything at full price. On a subscription these draw on plan limits.

## What this means for the trial

**Measure, per task and option:** input, cache-read, cache-write and output tokens and plan usage (`/usage` "Prompt cache (main)" line, or the status line's `prompt_cache` and `context_window` fields, [statusline](https://code.claude.com/docs/en/statusline)); context size at task start; every compaction's trigger and time (`PreCompact`/`PostCompact` hooks); each saved `compact_summary` scored against the task record, pull request and `git log` for false claims, missing decisions, owner instructions and open items, and wrong IDs or paths; rule breaches (task-prefixed checkpoints, session outcome, unrequested commits), owner corrections, redone work, review findings. Pin version, model, effort and `promptCacheTtl`; record subscription or API; keep logs outside the repository, as `AGENTS.md` requires.

**Failure signs:** a summary claiming work done, tested or approved with no commit, pull request or command output behind it; conversation-only rules stop being followed; an earlier plan or decision resurfaces; Claude acts on file contents it no longer holds; a compaction nobody ran, mid-task or while idle; `Autocompact is thrashing` or `Prompt is too long`; the `/compact` text executed; slow compaction after a pause (cold cache).

**Proposal (not adopted): task-boundary text**, worded as content to keep, never as actions, because of [#20370](https://github.com/anthropics/claude-code/issues/20370):

```text
/compact Task boundary: <TASK-ID> is finished; next is <NEXT-ID>. This text lists what to keep; it asks for no action. Keep: (1) milestone ID, next task ID and its record path; (2) per finished task: ID, branch, PR number and state, last commit, files changed, tests run and results; (3) decisions with reasons, and owner instructions given only in conversation, quoted exactly; (4) anything unfinished, failing, skipped or promised. Drop file contents, tool output and abandoned approaches. Mark "unverified" anything no commit, PR or command output shows; never call work done, reviewed or approved without that evidence.
```

First prompt afterwards: "Run `wf next`, reread the task record, and check `git status` and `git log`; trust them over the summary and list any differences." The count of differences measures summary fidelity. The same list as a CLAUDE.md section, so unplanned auto-compactions are asked to follow it, was adopted in MAINT-0006 (`templates/claude/compact-instructions.md`); a `SessionStart` hook with matcher `compact` that prints `wf next` still needs owner approval.
