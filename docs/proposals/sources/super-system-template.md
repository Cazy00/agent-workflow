## Operating model

- **Roles.** One human **owner** ("mandate, priority, irreversibles; answers in a word; silence has a recorded default"). One AI **verifier**, a scheduled task, hourly at most, that "grades, refuses, records, reports; never writes product". AI **builders** as lanes, one order each, each in its own Git worktree, dispatched as `claude -p "<order>"`; "they never grade themselves and never dispatch". A **hostile reviewer** in a separate context reviews design and architecture "until its blocker list is empty".
- **Session contract (A4).** Start: read Part A, `PORTFOLIO.md`, the active project's `STATE.md`, then `YOU.md`. End: rewrite `STATE.md`, append one line to `LOG.md` ending in an outcome word, regenerate the dashboard. Report ≤ 8 lines, "numbers from files never from memory". If `STATE.md` is stamped more than two days ago, re-verify before trusting it.
- **Records, never mixed.** Charter (`MANDATE.md`, the owner's words verbatim, dated, `**M-n.**` markers; superseded lines kept), rules (constitution + checks), procedures (`RUNBOOK.md`), status (`STATE.md`, rewritten), decisions (`DECISIONS.md`, one line each), archive (git + `LOG.md`, append only). Plus `PLAN.md`, `LESSONS.md` (notes capped at 20; "a lesson becomes a check, or it is only a note"), `ACCEPTANCE.md` (`AC-nnn`, `method: automated | human | operational | inspection`, source), `ops/lanes/NEXT-N.md` (one order per lane).
- **Decision line format.** `D-nnn · question · owner · type · status Open/Proposed/Resolved/Superseded · before: implement|verify|accept|release|none · blocks: <orders|all|none> · silence: <default> · quote: "<owner's words>" (where, date)`.
- **Lane order (`LANE-ORDER.md`).** Mandate line; decisions it depends on; stage; acceptance IDs; design source; **model and effort**; limits, retries and stop conditions; task; an **executable acceptance command** ("verify it runs on the target machine before writing it down — an order with a command that cannot run is a defect of the order"); an **anti-vacuity mutation** ("the one-line change to the product that must make the acceptance go red; the lane shows the red run and the green run"); a handoff block with technical result, workflow result, outcome word and next action.
- **Lifecycle (B1).** 0 IDEA → 1 CHARTER → 2 RECON → 2b DESIGN → 2c ARCHITECTURE → 3 SPINE → 4 GROW → 5 SHIP, each with one gate. Side-states HOLD, PIVOT, CLOSED, "declared, never drifted into". Gates: CHARTER "owner approves"; RECON "the claim survived a written check" (competitors, law, existing code); DESIGN "a real user tries a prototype unaided; the user understood it unaided"; ARCHITECTURE "data model first — precision, identity, tenancy, time; threats; performance budget; reviewed by a hostile reviewer until the blocker list is empty, then signed"; SPINE "one thin path end to end that a person can touch; the measure's command exits 0"; GROW "one capability at a time, each with acceptance + mutation; each passes before the next starts"; SHIP "staged release behind a flag; a real person used it AND rollback was exercised once".
- **The one measure (A5).** "Each project has exactly one measure, written in its MANDATE, phrased so a non-technical person can check it. Commit counts, merges, rules and percentages are never reported as progress." `STATE.md` carries `Today: NO / YES` with the command and its result.
- **Pause (B2).** A `STOP` file at the root halts builders, the loop and the verifier. "Proof of pause: the beacon log shows `halted` and no work lines for one full cycle. Not 'I told it to stop' — the log shows silence." Resume order: delete STOP → re-verify STATE → regenerate dashboard → re-enable beats.
- **Pivot (B3).** New mandate line dated; old lines marked superseded, never deleted; one PIVOT line in the log; every open order re-cut or refused; "work that no longer serves any line is closed, not finished 'since we started'".
- **Guards on the verifier (B7).** Every number in a report generated from files by a script; the dashboard is the owner's independent view; if the verifier exceeds 30% of a project's commits, that is a flag in STATE; "any report the dashboard contradicts is a recorded verifier fault".
- **Token discipline (B8).** Reading budget per session about 1,500 words; archive opened only by targeted search; one verifier beat per hour; "builders on the cheaper model unless the order names otherwise; gate work on the stronger one"; every order carries a limit and a stop rule.
- **Corner cases (B9).** Owner unavailable → open decisions carry "silence means X", work proceeds on defaults, irreversibles wait. Session dies → next session reads STATE, else the LOG's last line. Production breaks → "declare INCIDENT in STATE, freeze features, fix, lesson becomes check, resume". A "quick fix" outside any order → refused. Verifier and builder disagree → the acceptance command decides.
- **Changing the constitution (B11).** Only the owner; a dated line at the bottom; "if a proposed change cannot say which failure it prevents or which cost it removes, it is not made".
- **B12** compresses, in the same words, several rules this workflow also has: missing information by its nature ("Waiting for an answer never becomes permission to invent one"); six session outcomes (`progress · ready-for-review · verified-complete · blocked · stopped-by-limit · no-progress`); a design record for money, stock, security boundaries, sync or irreversible data; two results per pilot (technical and workflow); "acceptance is not a declaration that the code or its security was audited"; acceptance IDs whose removed tags are removed proofs.

## What the seven checks actually enforce

All run from `run_all.sh` against `git archive main` extracted to a temp directory, never the checkout. Each prints `ok — …` or `FAIL — …` and exits non-zero on failure.

| Check | Mechanical rule | Strength |
|---|---|---|
| `mandate_check.py` | Every `projects/*/ops/lanes/NEXT-[0-9].md` has `Mandate: M-n` and that `**M-n.**` marker exists in the project's `MANDATE.md` | Real reference check, regex level |
| `mutation_required.py` | Every live order (no `## HOLD`) contains a fenced code block and the word "mutation" (case-insensitive) anywhere | Presence only; satisfied by the template text itself |
| `secret_scan.py` | Strong patterns (private keys, AWS/OpenAI/GitHub/Slack/Google key shapes) fail; weak `password=…` patterns are reported; allowlist file | Useful, generic, small |
| `duplicate_block.py` | Counts identical 8-line windows shared across `.py`/`.js` files under `projects/`; may not grow past `baseline.json` | Ratchet; Python and JavaScript only |
| `import_exists.py` | Every top-level Python import resolves to stdlib, an installed package, a local module or `known_deps.txt` | Python only |
| `decision_block.py` | Register lines must parse (fail closed); IDs unique; `Resolved` needs a non-empty `quote:` or `ref:`; every order has a `Decisions:` line citing existing IDs; an Open/Proposed decision with `before:` ≤ the order's stage blocks it; `blocks:` can name orders; cross-project `<P> D-nnn` | Real gate logic; but "the owner's words" is any text after `quote:` |
| `acceptance_map.py` | `AC-nnn` unique across projects, each with a `method:`; orders cite defined IDs; `AC-nnn` tags in `test*.py/js/ts/swift` files must be defined; an (ID, file) mapping in `baseline.json` may not disappear | Same idea as this workflow's `tests/acceptance-map.json` check, without execution evidence |

`CHECKS/EXTERNAL.md` lists sixteen AI-coding failure modes (error masking, forgetting the goal, confident false reports, self-grading, security holes, duplication, boundary drift, no clean-up, churn, machinery instead of product, over-complication, not checking competitors, degrading over long runs, hallucinated packages, leaked secrets, trivial mistakes), each marked check / partial / watched, with a rule: "never both a check and a rule for the same thing". Its research citations (GitClear, Georgia Tech, OX Security, CSA, SlopCodeBench, Packmind, all dated 2026) were not verified by the note-taker.

## Tools

- `tools/dashboard.py` writes `<vault>/DASHBOARD.md` from `main`: portfolio table; the one measure per project from `STATE.md`; check results; "Waiting on you" (Open/Proposed decisions via `open_decisions.py`, with `before:` and `silence:`); last two LOG lines per project; trust panel (verifier commit share of last 50 commits, STOP present/absent, beacon freshness, "numbers typed by hand: 0").
- `tools/graph_map.py` (about 450 lines) builds a deterministic, token-free map of documents, concepts (from an owner-editable `CONCEPTS.md` alias list), mandate lines, decisions, acceptance IDs, checks and code modules on `main`; writes `graph.json`, a self-contained `graph.html`, `GRAPH_REPORT.md` and one Obsidian note per node. Archive folders and files over 20,000 words are excluded and listed. Every edge is structural; nothing is inferred.
- `tools/loop.sh`: every 300 s, if `STOP` exists write `halted` to `.git/beacon.log` and skip; else run checks, dashboard, map, optional `dispatch_lanes` hook (empty by default; reference snippet uses `git worktree add -B lane/N` and `claude -p … --permission-mode acceptEdits`), write a `tick` line. Pid-locked; macOS `caffeinate`.
- `scheduled-task/VERIFIER-BEAT-PROMPT.md`: the five-step prompt for the hourly verifier (STOP check; read three pages plus `YOU.md`; run checks and the measure's command, grade lane branches against their order, merge or refuse; answer `YOU.md` lines with `→`, record decisions only by quoting; rewrite STATE, append LOG, regenerate dashboard and map, commit; report ≤ 8 lines).
- `INSTALL.sh`: `git init`, branch `main`, default user "owner", `.gitignore`, one commit, run checks. The handover claims install "in ten steps (about 30 minutes)".
- `install-graphify.command`: installs the official Graphify skill; `GRAPHIFY-TRIAL.md` bounds a trial and asks for technical and workflow results separately.

## What the template does not have

No usage or spending accounting across orders (each order states a limit; nothing sums or checks them). No duplicate-claim prevention beyond the loop's pid lock. No crash recovery beyond "read STATE, else the last LOG line". No owner/worker identity separation (one Git user). No independent code review as a step (the verifier grades against the acceptance command; hostile review is at design and architecture only). No test-execution evidence (the lane reports its red and green runs; nothing records that they ran). No path classification or protected-path rule beyond "protected files change only with the owner's yes". No tool-neutrality (Obsidian, `claude -p`, macOS). No stated procedure after SHIP for maintenance, upgrades or workflow versioning. Its approval model is "the owner's quoted words in the register", enforced only as "some text after `quote:`", and its trust model is that the owner reads the dashboard.
